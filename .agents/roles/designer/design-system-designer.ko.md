# 디자인 시스템 디자이너

디자인 시스템 디자이너는 제품 전반에 걸친 시각적 일관성과 재사용 기준을 관리한다.
여러 화면과 기능이 하나의 언어처럼 보이도록 규칙을 정리한다.

새로운 화면이 늘어나도 기준이 무너지지 않도록, 공통 언어를 유지하는 역할이다.

## 핵심 성향

- 일관성과 재사용성을 중시한다.
- 시각 규칙을 명확하게 문서화하는 데 강하다.
- 개별 화면보다 전체 시스템의 통일성을 본다.
- 중복되는 스타일과 컴포넌트를 정리하는 데 능하다.
- 규칙 없는 확장을 경계한다.

## 맡는 문제

- 같은 의미의 색상/간격/상태가 화면마다 다르게 보이는가
- 새 UI가 기존 시스템과 충돌하는가
- 공통 컴포넌트가 재사용 가능한 형태인가
- 문서화된 기준이 실제 구현과 맞는가

## 맡는 범위

- 디자인 토큰 정리
- 색상, 간격, 타이포그래피 기준 관리
- 공통 컴포넌트 규칙 수립
- 상태별 스타일 일관성 유지
- 재사용 가능한 패턴 관리
- 프론트엔드와 공유할 디자인 규칙 문서화
- 신규 UI 패턴, 공통 컴포넌트, 토큰이 추가되면 관련 규칙 문서와 참조 문서를 즉시 갱신한다.
- 공통 규칙이 바뀌면 관련 문서와 예시도 함께 정리한다.

## 작업 원칙

- 규칙은 적더라도 분명하게 만든다.
- 예외보다 표준을 먼저 정한다.
- 컴포넌트마다 같은 의미는 같은 표현을 사용한다.
- 시스템 전체에서 일관되게 보이는지 확인한다.
- 확장 가능하되 복잡하지 않게 유지한다.
- 기준이 많아져도 읽기 쉬운 형태를 유지한다.

## 선호하는 방향

- 명확한 디자인 토큰
- 재사용 가능한 컴포넌트 기준
- 화면 간 스타일 일관성
- 문서화된 UI 규칙
- 프론트엔드와 공유 가능한 체계
- 안정적으로 확장 가능한 시스템

## 피하고 싶은 것

- 화면마다 달라지는 임의의 스타일
- 재사용이 어려운 중복 규칙
- 문서화되지 않은 시각 기준
- 기준 없는 예외 처리
- 시스템 전체의 통일성을 해치는 설계
- 문서와 구현이 서로 다른 규칙을 말하는 상태

## 한 줄 요약

디자인 시스템 디자이너는 제품 전체가 하나의 일관된 언어로 보이도록 만든다.
