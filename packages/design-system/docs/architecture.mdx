## 아토믹 패턴

`src/components/`는 아토믹 디자인 3층으로 나뉩니다. 판정 기준은 "무엇을 import 하는가"로 기계적으로 정합니다.

| 층 | 정의 | import 규칙 | 현재 |
| --- | --- | --- | --- |
| **atoms** | 더 쪼갤 수 없는 단일 요소 | 다른 컴포넌트 import 금지 — `core/` 토큰과 테마만 | 13개 |
| **molecules** | 기본 요소 여러 개를 하나의 계약으로 묶은 단위 | 아톰 import 가능 | 6개 |
| **organisms** | 제품 화면에서 반복되는 UI 블록 | 아톰·몰레큘 import 가능 | 2개 |

### 분류 예시로 보는 판정

- `Switch` → **atom**. 트랙+썸이지만 하나의 조작 단위, 내부에 다른 컴포넌트 없음.
- `TextInput` → **molecule**. 라벨 + 필드 + 헬퍼 텍스트 세 요소가 한 계약(`label`, `helperText`, `error`)으로 묶임.
- `Modal` → **molecule**. 백드롭 + 카드 + 제목 조합.
- `SettingRow` → **organism**. `Typo` 두 개 + `Switch`를 조합한 설정 화면 블록. 예시 앱에서 반복 등장해 승격됨.

### 승격 규칙

organism은 미리 만들지 않습니다. **예시/실제 화면에서 같은 조합이 2번 이상 반복될 때** 추출해서 승격합니다 (ProfileHeader, SettingRow가 이 경로로 생성됨).

## 현재 분류

- **atoms (13)**: Button, Typo, Avatar, Badge, Chip, Divider, Switch, Checkbox, Radio, Slider, ProgressBar, Skeleton, Spacer
- **molecules (6)**: TextInput, TextArea, SegmentedControl, Modal, Tooltip, Toast
- **organisms (2)**: ProfileHeader, SettingRow

## 크로스플랫폼 구조 — 컴포넌트당 3파일

```text
src/components/<tier>/<Name>/
├─ <Name>.types.ts     # Web/RN 공통 props 계약 — 플랫폼 타입 금지
├─ <Name>.web.tsx      # 순수 DOM + ARIA (react-native, react-native-web import 금지)
└─ <Name>.native.tsx   # react-native (Pressable/View, accessibilityRole/State)
```

- 치수·스케일은 전부 `src/core/tokens/`의 단위 없는 상수 — 양 플랫폼이 같은 숫자를 소비해 디자인 동일성을 코드로 강제
- 상태 계산(버튼 상태, 이니셜 추출 등)은 `src/core/state/`의 순수 함수
- `core/`는 react/react-native import 금지
- 진입점 분기는 `package.json` conditional exports (`react-native` → index.native.ts, `browser`/`default` → index.web.ts)

## 새 컴포넌트 추가 체크리스트

1. 층 판정 (위 import 규칙 기준) → `src/components/<tier>/<Name>/` 3파일 작성
2. 치수는 `core/tokens/`에 상수 추가 — 컴포넌트 파일에 매직 넘버 금지
3. `src/index.web.ts` + `src/index.native.ts` 양쪽에 export (계약 동일 유지)
4. 문서: `docs/components/<tier>/<이름소문자>.mdx` — **소스와 같은 층 폴더**. `pnpm docs:check`가 분류 일치까지 검사해서 어기면 실패
5. 데모: `apps/docs/components/demos.tsx`에 `<이름>Demo` 등록 (MDX에서 태그로 사용)
6. 스토리 + play 테스트: `src/components/__stories__/` — [Testing 문서](/docs/engineering/testing) 규칙 참고
7. `pnpm typecheck` + `pnpm docs:check` + `pnpm test:ui` 통과
