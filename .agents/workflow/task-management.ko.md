# Task Management Rules (태스크 관리 규칙)

## 개요

AI 에이전트가 태스크를 작성, 저장, 관리할 때 따라야 하는 규칙입니다.

---

## 1. 태스크 작성 전 확인사항

### 필수 질문

- 태스크의 범위와 목표가 명확한가?
- 기존 태스크와 중복되지 않는가?
- 의존성이 있는 다른 태스크가 있는가?

### 복잡도 판단 기준

| 복잡도 | 기준                          | 파일 구조                      |
| ------ | ----------------------------- | ------------------------------ |
| 간단   | 단일 기능, 1-2개 파일 수정    | 단일 .md 파일                |
| 보통   | 여러 파일 수정, 단일 도메인   | 단일 .md 파일                |
| 복잡   | 여러 도메인, 단계별 진행 필요 | 폴더 + README.md + 하위 파일 |

---

## 2. 태스크 저장 워크플로우

### Step 1: 태스크 초안 작성

- 사용자 요청 분석
- 관련 코드/문서 조사
- 태스크 초안을 메시지로 작성 (파일 저장 전)

### Step 2: 사용자 확인 (필수)


AskUserQuestion 도구 사용:

"이 태스크를 `tasks/active/[경로]`에 저장할까요?"

옵션:
- 저장 (권장)
- 수정 후 저장
- 저장하지 않음


### Step 3: 파일 저장

- 승인 후에만 파일 생성
- 경로: tasks/active/[YYYY-MM-DD]-[task-name].md

### Step 4: 작업 시작

- 태스크에 따라 순차적으로 진행
- 진행 상황을 태스크 파일에 업데이트

---

## 3. 파일 네이밍 규칙

### 형식


[YYYY-MM-DD]-[task-name].md
[YYYY-MM-DD]-[task-name]/README.md


### 예시


# 간단한 태스크
2026-01-27-fix-login-bug.md
2026-01-27-add-logout-button.md

# 복잡한 태스크
2026-01-27-auth-system-refactor/
├── README.md
├── 01-analysis.md
├── 02-implementation.md
└── 03-migration.md


### task-name 작성 규칙

- kebab-case 사용
- 동사로 시작 (`add`, fix, update, refactor, `implement`)
- 명확하고 간결하게 (3-5 단어)

---

## 4. 상태 전환 규칙

### Active → Complete

조건:

- [ ] 모든 완료 조건 체크박스 [x] 처리됨
- [ ] 검증 방법 실행 완료
- [ ] 사용자 확인 완료

작업:

1. 태스크 파일의 상태를 Complete로 변경
2. 파일을 complete/ 폴더로 이동
3. 완료 일자 추가

---

### Active → Backlog

조건:

- 우선순위 변경
- 블로커 발생
- 사용자 요청

작업:

1. 태스크 파일의 상태를 Backlog로 변경
2. 보류 사유 기록
3. 파일을 backlog/ 폴더로 이동

---

### Backlog → Active

조건:

- 블로커 해결
- 우선순위 상승
- 사용자 요청

작업:

1. 태스크 파일의 상태를 Active로 변경
2. 재개 일자 및 사유 기록
3. 파일을 active/ 폴더로 이동

---

## 5. 태스크 파일 업데이트 규칙

### 업데이트 시점

- 태스크 단계 완료 시
- 블로커 발생 시
- 방향 변경 시
- 완료 조건 달성 시

### 업데이트 내용

- 완료된 항목 체크 [x]
- 진행 로그 추가 (선택사항)
- 발견된 이슈/변경사항 기록

### 예시


## 완료 조건

- [x] 조건 1 (2026-01-27 완료)
- [ ] 조건 2
- [ ] 조건 3

## 진행 로그

- 2026-01-27: 조건 1 완료, 조건 2 진행 중


---

## 6. 특수 상황 처리

### 태스크 취소

- 상태를 Cancelled로 변경
- 취소 사유 기록
- complete/ 폴더로 이동 (기록 보존)

### 태스크 분할

- 원본 태스크에서 분할 사유 기록
- 새로운 태스크 파일 생성
- 상호 참조 링크 추가

### 태스크 병합

- 병합 대상 태스크들에 병합 사유 기록
- 새로운 통합 태스크 생성
- 원본 태스크는 Cancelled 처리

---

## 7. 금지 사항

- 사용자 확인 없이 태스크 파일 저장
- 완료되지 않은 태스크를 complete/로 이동
- 태스크 없이 대규모 변경 작업 진행
- 태스크 파일 삭제 (취소 시에도 보존)
