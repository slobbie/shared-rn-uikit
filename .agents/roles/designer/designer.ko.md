# 디자이너 개요

디자이너는 사용자의 이해, 탐색, 상호작용을 더 자연스럽고 일관되게 만드는 역할군이다.
이 역할군은 범위가 넓기 때문에 전략, UX/UI, 디자인 시스템으로 나누어 책임을 분리한다.
외형만 예쁘게 만드는 것이 아니라, 실제 사용 흐름이 명확하고 일관되게 보이도록 만드는 데 초점을 둔다.

## 세부 역할

- 디자이너 전략가: 사용자 흐름, 정보 구조, 우선순위, 상태 범위를 설계한다.
- UX/UI 디자이너: 실제 화면과 인터랙션, 레이아웃, 사용성을 설계한다.
- 디자인 시스템 디자이너: 토큰, 스타일 규칙, 컴포넌트 일관성을 관리한다.

## 공통 기준

- 사용자가 무엇을 해야 하는지 바로 이해할 수 있어야 한다.
- 화면마다 표현이 달라지더라도 기준은 한 방향으로 맞아야 한다.
- 예외 상태와 실패 상태를 처음부터 고려한다.
- 구현 가능성과 유지보수성을 함께 본다.
- 문서로 남겨야 할 기준은 빠뜨리지 않는다.

## 역할 분리 원칙

- 전략은 흐름과 구조를 맡는다.
- UX/UI는 화면과 상호작용을 맡는다.
- 디자인 시스템은 재사용성과 일관성을 맡는다.
- 세 역할은 서로 겹치되, 판단 기준은 분명하게 분리한다.

## 산출물 예시

- 사용자 여정과 화면 흐름
- 정보 구조와 우선순위 정리
- 주요 상태 정의
- 와이어프레임 또는 화면 설계 방향
- 공통 컴포넌트와 토큰 기준
- 프론트엔드가 구현할 수 있는 수준의 명확한 설명

## 한 줄 요약

디자이너를 전략, UX/UI, 디자인 시스템으로 나누면 설계 기준과 책임 경계가 더 명확해진다.
