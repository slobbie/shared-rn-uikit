## 검증 계층

품질 검증은 4개 층으로 나뉩니다. 아래로 갈수록 실제 사용자 동작에 가깝습니다.

| 층 | 명령 | 잡는 문제 |
| --- | --- | --- |
| 타입 | `pnpm typecheck` | 계약(props) 위반, 잘못된 import — 5개 워크스페이스 전체 |
| 문서 동기화 | `pnpm docs:check` | 공개 API에 있는데 문서가 없거나, 소스 분류(atoms/molecules/organisms)와 문서 위치가 다른 컴포넌트 |
| 인터랙션 | `pnpm test:ui` | 클릭·입력했을 때 실제 동작과 ARIA 상태 — 실브라우저(Playwright) |
| 통합 빌드 | `pnpm docs:build` / vite build / `expo export` | 번들 레벨 회귀 (웹 번들에 RN 코드 유입, Metro 해석 실패 등) |

## 인터랙션 테스트 — 스토리 = 테스트

문서·데모는 Fumadocs가 담당하므로 **스토리북은 테스트 하네스 전용**입니다. 각 스토리가 곧 테스트 케이스입니다.

구조 (CSF3):

```tsx
export const Switches: StoryObj = {
  render: () => <SwitchExample />,          // 격리 렌더 — 이 자체로 렌더 스모크 테스트
  play: async ({ canvasElement }) => {      // 렌더 후 실브라우저에서 실행
    const canvas = within(canvasElement);
    const sw = canvas.getByRole('switch');
    await expect(sw).toHaveAttribute('aria-checked', 'false');
    await userEvent.click(sw);               // 진짜 클릭 이벤트
    await expect(sw).toHaveAttribute('aria-checked', 'true');
  },
};
```

원칙:

- **역할(role)로 조회** — `getByRole('switch')`, `getByRole('dialog')`. 접근성 시맨틱이 깨지면 테스트가 먼저 깨진다.
- **ARIA 상태를 단언** — `aria-checked`, `aria-invalid`, `aria-busy`, `aria-valuenow`. 시각이 아니라 의미를 검증.
- **portal 컴포넌트**(Modal, Toast)는 canvas 밖 `document.body`로 렌더되므로 `within(canvasElement.ownerDocument.body)`로 조회.
- **라벨이 변하는 요소는 참조 고정** — Button은 loading 중 텍스트가 '…'로 바뀌므로, 이름으로 재조회하지 말고 처음 찾은 요소 참조에 단언한다.
- **시간 의존 동작은 `waitFor`** — Toast 자동 숨김, Button loading 해제.

## 실행

```bash
# 방법 1 — dev 서버 상대로
pnpm storybook            # 터미널 1: localhost:6006
pnpm test:ui              # 터미널 2

# 방법 2 — CI용 정적 빌드 상대로
pnpm --filter @package/design-system build-storybook
npx http-server packages/design-system/storybook-static -p 6006 --silent &
pnpm test:ui
```

`test-storybook`은 `--maxWorkers 1`로 고정되어 있습니다 — 병렬 워커가 페이지 네비게이션을 겹치면 "Execution context was destroyed" flake가 발생합니다. 전체 20 테스트에 ~6초라 직렬로 충분합니다.

## 현재 커버리지 (20 테스트)

| 스토리 | 검증 내용 |
| --- | --- |
| Forms/Checkboxes · Radios · Switches | 클릭 → `aria-checked` 토글, Radio 상호배제 |
| Forms/TextInputs | 짧은 비밀번호 → `aria-invalid` + 에러 문구, 조건 충족 시 해제 |
| Forms/TextAreas | 입력값 반영 |
| Forms/SegmentedControls | 탭 클릭 → `aria-selected` 전환 |
| Forms/Sliders | 값 변경 → 연동 캡션 갱신 |
| Display/Typos | 시맨틱 헤딩 레벨 (h1/h3) |
| Display/Avatars | 이니셜 규칙 (한글 첫 글자 / 라틴 두 단어 HK) |
| Display/Chips | 클릭 → `aria-pressed` 토글 |
| Display/ProgressBars | 버튼 클릭 → `aria-valuenow` 30→40 |
| Display/Badges · Dividers · Skeletons | 렌더 스모크 |
| Overlay/Buttons | disabled, 클릭 → `aria-busy` → 해제 |
| Overlay/Modals | 열기 → `role=dialog`+`aria-modal` → ESC 닫기 |
| Overlay/Tooltips | 호버 → `role=tooltip` 표시/해제 |
| Overlay/Toasts | 표시 → `role=status` → duration 후 자동 숨김 |
| Organisms/SettingRows | 내부 Switch 토글, disabled 전파 |
| Organisms/ProfileHeaders | 헤딩·배지·아바타 이니셜 |

## 새 컴포넌트의 테스트 추가 규칙

1. `src/components/__stories__/` 해당 그룹 파일에 스토리 추가 (조작 가능하면 `play` 필수)
2. 상태가 필요하면 스토리 위에 `XxxExample` 래퍼 컴포넌트로 useState 캡슐화
3. 단언은 role + ARIA 속성 기준 — 텍스트/스타일 단언은 최후 수단
4. `pnpm test:ui` 통과 확인 후 머지
