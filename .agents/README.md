# .agents/

## 가장 중요한 원칙

- 이 폴더는 `shared-rn-uikit` 프로젝트 안에서만 사용하는 **로컬 에이전트 운영 문서**입니다.
- 이 프로젝트에서 에이전트 관련 문서는 모두 프로젝트 루트의 `.agents/` 아래에서 관리합니다.
- 이 폴더는 **별도 저장소로 운영하지 않습니다**.
- 외부에서 복사해 올 때 `.agents/.git` 같은 중첩 Git 메타데이터가 남아 있으면 먼저 제거합니다.
- 실제 작업 기준 문서는 `.md` 파일이며, `.ko.md`는 사람용 한국어 참고 문서입니다.

이 문서는 `shared-rn-uikit`에서 에이전트가 어디를 먼저 참고해야 하는지와, `.agents/` 폴더가 어떤 역할을 하는지 설명합니다.

## 이 폴더의 역할

- 에이전트가 참고할 문서의 우선순위를 정합니다.
- `shared-rn-uikit`의 실제 구조에 맞는 작업 기준을 제공합니다.
- 공통 규칙, 도메인, 워크플로우, 인프라 문서를 한곳에서 관리합니다.
- 사람이 `.agents/` 구조를 빠르게 이해할 수 있도록 돕습니다.

## 이 프로젝트에서의 위치

- `.agents/` 폴더는 프로젝트 루트에 둡니다.
- 에이전트 관련 운영 문서는 `.agents/` 안에서 관리합니다.
- `global.md`는 에이전트가 가장 먼저 참고하는 라우팅 문서입니다.
- `.ko.md` 파일은 사람을 위한 한국어 참고 문서입니다.

## 현재 프로젝트 기준 핵심 구조

- `app/`: Expo Router 화면 및 라우트 엔트리
- `shared/ui/`: 재사용 UI 컴포넌트
  - `atoms/`
  - `molecules/`
  - `layout/`
  - `utils/`
- `shared/utils/lib/`: 테마, 공통 유틸리티, 컨텍스트
- `stories/`: Storybook 문서/스토리 보조 파일
- `.storybook/`: Storybook 웹 설정
- `.github/workflows/`: Storybook 배포 워크플로우

## 폴더 구성

### `roles/`
- 역할 기반 작업 지침을 둡니다.
- 현재 프로젝트에서 실질적으로 우선 사용하는 역할은 `frontend/`입니다.
- 다른 역할 폴더는 당장 활성 운영 범위가 아니어도 참조본으로 남겨둘 수 있습니다.

### `domain/`
- UI kit의 도메인 개념, 컴포넌트 분류, 테마 구조를 둡니다.

### `infra/`
- Expo 실행 방식, Storybook 빌드/배포, GitHub Actions 같은 운영 정보를 둡니다.

### `testing/`
- 컴포넌트 검증 기준, 회귀 확인 포인트, 테스트 전략을 둡니다.

### `workflow/`
- 작업 생성, 진행, 문서 동기화 절차를 둡니다.

### `rules/`
- 반드시 지켜야 하는 공통 규칙과 가드레일을 둡니다.

### `templates/`
- 반복해서 쓸 수 있는 문서 양식과 작업 템플릿을 둡니다.

### `tasks/`
- 진행 중/보류/완료 작업 문서를 보관하는 작업 공간입니다.

### `global.md`
- 어떤 작업에서 어떤 문서를 먼저 봐야 하는지 알려주는 최상위 라우팅 문서입니다.

## 셋업 원칙

### 1. 원문과 참고문서 구분
- 실제 작업 기준은 `.md` 파일입니다.
- `.ko.md` 파일은 사람 읽기용 참고 문서입니다.
- 한/영 문서는 의미를 맞춰 함께 유지합니다.

### 2. 프로젝트 기준 유지
- `.agents/` 문서는 반드시 `shared-rn-uikit`의 실제 구조와 스택을 반영해야 합니다.
- Expo, Expo Router, Storybook, `@shared` alias, `shared/ui` 구조가 바뀌면 관련 문서를 함께 수정합니다.
- Next.js, Tailwind, 백엔드 중심 설명처럼 현재 프로젝트와 맞지 않는 문구는 남기지 않습니다.

### 3. 라우팅 갱신
- 폴더 구조가 바뀌면 `global.md`와 관련 문서를 함께 수정합니다.
- 공통 컴포넌트 규칙이나 테마 규칙이 바뀌면 `domain/`, `rules/`, `roles/frontend/`를 함께 갱신합니다.

## 추천 사용 순서

1. `global.md`를 먼저 봅니다.
2. 프론트 작업이면 `.agents/roles/frontend/`를 먼저 봅니다.
3. 공통 UI 구조나 토큰 규칙이 필요하면 `.agents/domain/`, `.agents/rules/`를 봅니다.
4. 실행/배포 관련이면 `.agents/infra/`를 봅니다.
5. 작업 기록이 필요하면 `.agents/workflow/`, `.agents/tasks/`를 봅니다.

## 유지보수 체크리스트

- `.agents/` 경로가 최신 상태인가?
- 한/영 문서가 같은 의미를 유지하는가?
- 실제 프로젝트 구조와 문서 설명이 일치하는가?
- placeholder 문구가 남아 있지 않은가?
- 새 컴포넌트/토큰/패턴이 관련 문서에 반영되었는가?

## 한눈에 보는 관계

- `global.md`: 어디로 갈지 결정
- `roles/frontend/`: 프론트 작업 방식 정의
- `domain/`: UI kit 구조와 개념 정의
- `rules/`: 공통 구현 규칙 정의
- `infra/`: 실행/빌드/배포 기준 정의
- `workflow/`: 작업 절차 정의
- `templates/`: 반복 문서 형식 정의

프로젝트 구조나 작업 방식이 바뀌면 이 문서와 `global.md`를 함께 수정해야 합니다.
