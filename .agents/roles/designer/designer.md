# Designer Overview

Designers make user understanding, navigation, and interaction feel more natural and consistent.
Because the scope is broad, the role is split into strategy, UX/UI, and design systems to keep responsibilities clear.
The focus is not just on visual polish, but on making the real user flow understandable and coherent.

## Subroles

- Designer Strategist: designs user flows, information structure, priorities, and state scope.
- UX/UI Designer: designs the actual screens, interactions, layout, and usability.
- Design System Designer: manages tokens, style rules, and component consistency.

## Shared Standards

- Users should immediately understand what they need to do.
- Even if individual screens differ, the standards should point in one direction.
- Edge cases and failure states are considered from the start.
- Implementation feasibility and maintainability are considered together.
- Important standards should be documented, not left implicit.

## Role Separation Principles

- Strategy owns flow and structure.
- UX/UI owns screens and interactions.
- Design systems owns reuse and consistency.
- The roles may overlap, but their decision criteria should stay distinct.

## Example Deliverables

- User journeys and screen flows
- Information architecture and priority ordering
- Key state definitions
- Wireframes or screen-direction guidance
- Common component and token standards
- Clear explanations that frontend can implement

## One-Line Summary

Splitting design into strategy, UX/UI, and design systems makes design standards and responsibility boundaries much clearer.
