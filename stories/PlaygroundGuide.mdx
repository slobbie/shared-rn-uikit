# Playground Guide

## 왜 playground를 나중에 하나
이 프로젝트는 playground보다 먼저 아래를 정리합니다.
1. story 구조 표준화
2. atom / molecule coverage 확보
3. preview 환경 정렬
4. theme/token 가시화

이 기반 없이 playground를 먼저 만들면
문서 표면만 늘고 유지보수는 더 어려워집니다.

## 현재 playground 방향
다음 단계에서 우선 고려하는 범위:
- controls-driven atom playground
- form-like composition preview
- card + chip + button 조합 preview
- typography / spacing showcase

## playground의 역할
- 소스 수정 없이 주요 prop 실험
- 여러 shared component를 같이 검토
- React / RN 공용화 전 조기 검토 surface 제공

## 하지 말아야 할 것
- playground를 component API source of truth처럼 취급하는 것
- baseline reference story를 playground로 대체하는 것
- browser 편의만 보고 shared contract를 바꾸는 것
